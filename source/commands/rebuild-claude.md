# /rebuild-claude 命令

## 角色

CLAUDE.md 重建执行者。项目目录/技术栈变化后，把根与一级子目录的 CLAUDE.md 更新到与现状一致。

## 铁律（违反 = 重建失败）

1. **先读后写**：重建前先读取现有 CLAUDE.md，在其之上更新而非推倒重写——已存在且合理的内容保留，只更新过时部分。
2. **根 CLAUDE.md 只写三样**：①目录架构索引描述 ②极简项目技术栈 ③机构/项目摘要描述。**严禁详细展开任何内容**——细节放子目录 CLAUDE.md，根只放指针。
3. **一级子目录 CLAUDE.md 可以详写**：目录职责、关键文件、约定都行。遵循渐进式读取原则——需要时才读子目录详情。
4. **黑名单跳过**：命中 `~/claude-template-distribute/blacklist.md` 的目录（.claude/、.git/、node_modules/ 等机器生成/配置目录）跳过不建，跳过必须在步骤 3 汇报里逐条列理由，不静默跳过。
5. **幂等**：已存在且合理 → 保留；过时 → 更新；缺失 → 创建。绝不无谓改动。

## 执行步骤

### 步骤 1：读黑名单 + 列目录

1. 读 `~/claude-template-distribute/blacklist.md`（本次执行只读一次）
2. 列出 `$PWD` 根目录与一级子目录

### 步骤 2：更新根 CLAUDE.md

1. **先 Read 现有 `$PWD/CLAUDE.md`**（不存在则新建），在其之上更新，不推倒重写
2. 内容只允许三样：
   - **目录架构索引描述**：一级子目录一览 + 一句话职责 + 指向各子目录 CLAUDE.md 的指针
   - **极简项目技术栈**：语言/框架/构建工具，几行内说完
   - **机构/项目摘要描述**：项目是干什么的，几句话说清
3. 详细内容一律指针化——渐进式读取，需要时才读子目录详情

### 步骤 3：更新一级子目录 CLAUDE.md

1. 逐个一级子目录判断：
   - 命中黑名单 → **跳过**（汇报时列理由）
   - 已有 CLAUDE.md → Read 后在其之上更新过时部分，合理内容保留
   - 缺失 → 新建
2. 内容允许详写：目录职责、关键文件、访问约定。生成物/测试/归档目录只写结构总览+访问约定；手写源码/文档目录（src/ docs/ tests/ config/ scripts/ 等）再加组件、功能、技术栈、依赖关系
3. 每个子目录 CLAUDE.md 只放该目录要点，不冗余、不写流水账

### 步骤 4：汇报

```
✅ 更新：根 CLAUDE.md / 子目录 N 个（新建 M 个）
⏭️ 跳过（黑名单/无变化）：目录 + 理由
⚠️ 警告：<如有>
```

## 触发场景

- 项目新增/删除了目录或模块，CLAUDE.md 与实际结构不符
- 技术栈/架构变动后想同步索引
- 用户敲 `/rebuild-claude`
